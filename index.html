Set Up the Arduino Uno Q via App Lab

Bring the board online with Arduino App Lab — see the App Lab documentation for reference.

The Uno Q is a dual-brain board: a Qualcomm Dragonwing QRB2210 (quad-core ARM Cortex-A53) running Debian Linux paired with an STM32U585 (Cortex-M33) microcontroller. App Lab runs on the Linux side and bridges to the MCU through its Bricks architecture, so it is the single tool for flashing sketches, managing Linux, updating firmware, and configuring Wi-Fi and SSH.

1

Download and install Arduino App Lab

Install the App Lab desktop application for Windows, macOS, or Linux from arduino.cc/software. App Lab talks to the board over USB and serves a browser-based WebUI. App Lab is also pre-installed on the Uno Q itself, so once the board is on your network you can reach its WebUI directly in a browser.

On Windows and macOS no manual drivers are needed. On a Linux desktop host, add a udev rule so App Lab can access the board over USB, then reload udev:

echo 'SUBSYSTEMS=="usb", ATTRS{idVendor}=="2341", ATTRS{idProduct}=="0078", MODE="0660", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/60-arduino-uno-q.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
2

Connect the board over USB-C

Plug the Uno Q into your computer with a USB-C cable and wait roughly 30 seconds for the board to boot — watch for the heartbeat / RGB LED activity before it becomes detectable. Connect the board directly; avoid USB hubs during first setup.

Use a USB-C data cable, not a charge-only / power-only cable. Charge-only cables carry no data and will prevent App Lab from ever detecting the board.

3

Let App Lab detect the board

Open App Lab. It scans for boards on USB, which can take a little while. If several boards or connections appear, select the one you want — only one board can be connected at a time. Once connected, App Lab opens on the Examples section.

Only one board can be connected to App Lab at a time. If detection is ambiguous, disconnect any other Arduino boards so the Uno Q is the only candidate.

4

Accept the first-install update dialogue

The very first time the board connects, App Lab shows an update dialogue that refreshes the board firmware and Linux image. You must accept it and let the update run to completion before doing anything else.

This update is required, not optional. The update only finishes installing after the reboot in Step 02 — without that reboot the update stays half-applied and later steps (such as installing Tailscale) will fail to install. Complete this update now, then proceed to the reboot in Step 02 before continuing.

5

Set up the first-run Linux credentials

During onboarding App Lab prompts you to set a board name and create the Linux account used for SSH. On the Uno Q the username is fixed as arduino and the out-of-box default password is also arduino.

FieldValue
Usernamearduino
Default passwordarduino

Change the password immediately. The default arduino / arduino credential is well known — leaving it in place exposes a full Debian Linux machine with sudo on your network.

6

Join Wi-Fi and find the board IP

The easiest path is the App Lab onboarding Wi-Fi step, or click the network icon in App Lab's upper-right to pick an access point and enter its password. The Uno Q has dual-band Wi-Fi 5 (2.4 and 5 GHz). From a shell you can connect manually:

nmcli device wifi list
sudo nmcli device wifi connect 'YOUR_SSID' password 'YOUR_WIFI_PASSWORD'

Once connected, find the board's address with hostname -I or by inspecting the wlan0 interface:

hostname -I
ip addr show wlan0

The board also advertises itself over mDNS, so you can usually reach it as arduino.local without knowing its IP. After Wi-Fi is configured you can unplug USB and power the board from a 5V/3A USB-C supply for headless use — App Lab will rediscover it over the network. WebUI Brick apps are then served at http://<board-ip>:7000.

7

Enable SSH and connect

SSH is not enabled by default. From an App Lab terminal or ADB shell, install and start the SSH server:

sudo apt update && sudo apt install -y openssh-server
sudo ssh-keygen -A
sudo systemctl enable ssh && sudo systemctl start ssh

Then connect from your computer using the arduino account and the mDNS hostname:

ssh arduino@arduino.local

If arduino.local does not resolve on your network, substitute the IP you found above, for example ssh arduino@192.168.1.50. You can also add the board as a host in the VS Code Remote - SSH extension for full remote development.

02
02

Reboot to Finish the Update

A clean restart finishes installing the App Lab update and activates SSH and your saved config.

This reboot is required, not optional. The App Lab update dialogue from Step 01 only finishes installing after a restart. If you skip this reboot, the next step — installing Tailscale — will fail.

1

Issue the reboot

From a terminal on the board (or your existing SSH session) run the standard Linux command. Enter your Linux password if prompted (default arduino unless you changed it during setup).

sudo reboot

No terminal handy? A long press of 5+ seconds on the board's power button reboots the Linux side as well.

On this hybrid board sudo shutdown now reboots instead of powering off. For a true shutdown, use sudo halt.

2

Wait for it to come back

Your SSH session drops instantly (Connection closed by remote host) — that is expected, not an error. The board is unreachable for roughly 45–60 seconds while Debian and its services restart. Watch the LED matrix animation and wait for SSH to start accepting connections again before reconnecting.

Do not assume failure too early. A Connection refused on reconnect means the network is up but sshd hasn't finished starting — wait a few more seconds and retry rather than re-running setup.

3

Reconnect via SSH

Reconnect as the arduino user using the board's IP address. Wi-Fi credentials persist across reboots, so the board auto-rejoins the same network.

ssh arduino@<board-ip-address>

Default credentials are username arduino / password arduino. The system will keep nagging you until you change it — run passwd and set a new password immediately to keep the board secure on your network.

SSH From Anywhere With Tailscale

Reach your Uno Q from any network with a private mesh VPN — Tailscale is free for personal use.

Make sure the reboot from Step 02 has fully completed before you start. If the App Lab update has not settled, the Tailscale install below can fail partway through.

1

Create a free Tailscale account

Go to login.tailscale.com/start and sign in with an identity provider — Google, GitHub, Microsoft, Apple, or email all work. This automatically provisions your personal tailnet on the free Personal plan. You'll use this same account on every device.

2

On your Arduino Uno Q

Install Tailscale with the official script. It auto-detects the Uno Q's CPU architecture (arm64/aarch64 or armhf) and the Debian/Ubuntu apt repo, then installs the tailscale CLI and the tailscaled daemon as a systemd service that starts on boot.

curl -fsSL https://tailscale.com/install.sh | sh

Bring the device online and authenticate it to your tailnet with Tailscale SSH enabled in one step. This needs sudo because it controls the daemon and binds the SSH server:

sudo tailscale up --ssh

The command prints a https://login.tailscale.com/... URL. Open it in any browser, log in with the same account from above, and approve the device. The Uno Q is now a node on your tailnet and is opted in as a Tailscale SSH server.

If you already ran sudo tailscale up without --ssh, enable it afterward with no re-auth: sudo tailscale set --ssh.

Find the device's Tailscale address so you can reach it. Get the 100.x.y.z Tailscale IP, or list all nodes and their names:

tailscale ip -4
tailscale status

The device's MagicDNS hostname is its machine name (e.g. uno-q), or the fully-qualified <machine-name>.<tailnet>.ts.net shown in the admin console. MagicDNS is on by default, so you can use the short hostname instead of the IP.

3

On your other devices

Install Tailscale on whatever you'll connect from and sign in with the same account so both devices share the tailnet:

PlatformInstall
macOSMac App Store, tailscale.com/download/mac, or brew install tailscale
Windowstailscale.com/download/windows, then sign in
Linuxcurl -fsSL https://tailscale.com/install.sh | sh then sudo tailscale up
iOS / AndroidInstall the Tailscale app from the App Store or Google Play

Confirm both the Uno Q and the client appear with tailscale status, then connect from anywhere. Tailscale SSH authenticates via your tailnet identity, so no SSH keys or passwords are required:

tailscale ssh arduino@uno-q
tailscale ssh arduino@100.x.y.z

A standard ssh arduino@uno-q also works over the tailnet once MagicDNS is on. If hostname resolution ever fails, just use the 100.x.y.z Tailscale IP.

The free Personal plan covers up to 100 devices — far more than enough here. For a headless device, disable key expiry in the admin console (Machines > the device > Disable key expiry) so the Uno Q stays reachable without periodic re-authentication.

Enabling Tailscale SSH lets any tailnet user permitted by your ACLs connect as the specified local user without a password. On a single-user personal tailnet that's only you, and the default ACL already allows your own devices to SSH to each other. Keep your tailnet private and secure your Tailscale login with 2FA.

Install Claude Code + the cc Alias

Install Claude Code, Anthropic's official CLI, and wire up a one-letter cc shortcut.

1

Install Node.js

Claude Code is a Node.js package, so it runs the same on the Uno Q's ARM64 chip as on any x86 machine, as long as you have Node 18 or newer. The cleanest way on a board is nvm, which installs into your home directory and needs no sudo.

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install --lts && nvm use --lts

Prefer a system-wide install? Use apt instead, then check the version.

sudo apt update && sudo apt install -y nodejs npm
node --version
npm --version

The Debian/Ubuntu apt repos often ship an older Node. If node --version reports below 18, switch to nvm (above) or NodeSource. nvm also avoids the EACCES permission errors that sudo npm install -g tends to hit.

2

Install Claude Code

Install the CLI globally from npm, then confirm it is on the box. With nvm this needs no sudo.

npm install -g @anthropic-ai/claude-code
claude --version

For a full environment health check, run claude doctor.

3

If the 'claude' command isn't found

If running claude after installing gives command not found, the directory npm dropped the binary into isn't on your PATH. Add the local bin directory and reload your shell.

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc

This appends $HOME/.local/bin to your PATH in ~/.bashrc and reloads the shell so the claude command resolves immediately, and in every future terminal session.

4

Authenticate

Run claude and follow the login prompt to sign in with a Claude.ai Pro/Max or Anthropic Console account.

claude

On a headless board with no browser handy, you can authenticate with an API key instead. Add it to ~/.bashrc to make it persist.

export ANTHROPIC_API_KEY=sk-ant-...
5

Add the cc alias

The cc alias launches Claude Code hands-off and remotely steerable. Try it in the current shell first.

alias cc='claude --dangerously-skip-permissions --remote-control'

Then make it permanent by appending it to ~/.bashrc and reloading.

echo "alias cc='claude --dangerously-skip-permissions --remote-control'" >> ~/.bashrc && source ~/.bashrc

In plain terms: --dangerously-skip-permissions skips the interactive approval prompts before each file edit or command, which is handy on a headless board you control, and --remote-control lets you drive the session remotely (for example from the Claude mobile app) instead of only from the local terminal.

--dangerously-skip-permissions lets Claude read, modify, and run things without asking first. Only use it on a board you trust and control, never on a shared machine or untrusted network.

Go Public With a Cloudflare Tunnel

Use a Cloudflare Tunnel to expose a local service to the public internet — no port forwarding, no opening firewall ports.

1

Start a local web server

You need something listening on a local port for the tunnel to forward to. The quickest test is Python's built-in HTTP server on port 8080. The tunnel will forward to http://localhost:8080.

python3 -m http.server 8080

The python3 -m http.server example serves every file in the current directory to the entire internet. Run it from a directory you are comfortable exposing, or point the tunnel at your real app instead.

2

Install cloudflared on the board

The Uno Q is aarch64 (ARM64) — confirm with uname -m. The cleanest install on the Debian-based Uno Q image is the Cloudflare apt repository, which auto-selects the right architecture and gives you updates via apt upgrade.

sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo 'deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main' | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt-get update && sudo apt-get install -y cloudflared

If the apt repo is unavailable, download the ARM64 binary directly from GitHub instead.

curl -L --output cloudflared https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64
chmod +x cloudflared
sudo mv cloudflared /usr/local/bin/

Verify the install:

cloudflared --version

Match the binary to the architecture. Installing the arm64 build on a 32-bit (armv7l) OS — or vice versa — gives an Exec format error. Always confirm with uname -m first.

3

Quick tunnel (no account)

The fastest way to go public: point a quick tunnel at your local port. No Cloudflare account and no domain required.

cloudflared tunnel --url http://localhost:8080

cloudflared prints a random public URL of the form https://<random-words>.trycloudflare.com (for example https://happy-tree-cloud-1234.trycloudflare.com). Anyone can reach your local server at that URL while the command runs.

Quick tunnels are for demos and testing only: the URL changes on every restart, there is no uptime guarantee, and they are rate-limited. Use a named tunnel for anything you want to keep online.

4

Persistent named tunnel (free Cloudflare account)

For a stable URL on your own domain, create a free account at dash.cloudflare.com and add a domain whose nameservers point at Cloudflare (the zone). Then authenticate — on the headless Uno Q this prints a URL you open in a browser on another machine.

cloudflared tunnel login

Create the tunnel. This writes a credentials file to ~/.cloudflared/<UUID>.json and registers a persistent name.

cloudflared tunnel create uno-q

Write ~/.cloudflared/config.yml mapping a hostname to your local service. The final http_status:404 rule is a required catch-all.

tunnel: <UUID-from-create>
credentials-file: /home/<user>/.cloudflared/<UUID>.json
ingress:
  - hostname: app.example.com
    service: http://localhost:8080
  - service: http_status:404

Route DNS, creating a CNAME from your subdomain to <UUID>.cfargotunnel.com, then run the tunnel.

cloudflared tunnel route dns uno-q app.example.com
cloudflared tunnel run uno-q

Your server is now public at https://app.example.com with Cloudflare-managed TLS. To survive reboots and SSH disconnects, install it as a systemd service rather than leaving it in a shell.

sudo cloudflared service install
sudo systemctl enable --now cloudflared

A plain cloudflared tunnel run stops when your SSH session ends. The systemd service runs the tunnel from your config.yml at boot — the key to a reliable headless setup on the Uno Q.

A public tunnel exposes your service to the entire internet, bypassing your LAN firewall. Add authentication — such as Cloudflare Access — in front of anything sensitive before you expose it.

🎉 You're all set!

Your Uno Q is updated, reachable over Tailscale SSH from anywhere, running Claude Code, and able to serve a public site through Cloudflare.
