Your UNO Q. Your programs. No AI subscription.

You can run and edit every standalone sketch in this repository with free Arduino tools. You do not need an AI account, API key, paid coding assistant, or GitHub account to download the code. Start with a light show, then change a message or explore sensors at your own pace.

A sketch is an Arduino program saved in an .ino file. Compile means checking and translating that code for your board. Upload (also called flash) means installing it on the board.

Start here: Follow the Arduino IDE steps if you use Windows, macOS, or Linux on a separate computer. If you already have the UNO Q's Linux terminal open, follow the on-board terminal steps. Both paths run the same sketches.

1. Get your board ready

Gather these items before you begin:

  • An Arduino UNO Q. These sketches target its STM32U585 microcontroller, not an UNO R3 or UNO R4.
  • A USB-C data cable and a computer for the IDE path.
  • Internet access for the first downloads and board setup. The animations themselves do not need the internet.
  1. Complete Arduino's official UNO Q first setup with Arduino App Lab. Set up the board's Linux password and network, and apply the setup updates. App Lab is the board setup tool; it does not require an AI subscription.
  2. Let the board finish booting. Its Linux side manages communication and uploads to the microcontroller.
  3. Stop any running App Lab app before uploading a standalone sketch. An app can install its own sketch when it starts. If the old app returns after reboot, check its Run at startup setting in App Lab.
  4. For the first light show, leave external sensors, shields, and wires disconnected.

Uploading replaces the current microcontroller program. Save any source code you want to keep first. Uploading a sketch does not reinstall the board's Debian operating system. To return to an earlier sketch, upload its saved source again. Serial settings and messages in these examples are held in memory and are lost when the sketch restarts.

2A. Upload with the free Arduino IDE

This path runs on your computer. You do not need Git, Python, or a terminal.

  1. Install Arduino IDE 2 for your operating system.
  2. Download the repository: open agent-arduino on GitHub, select Code → Download ZIP, then extract the ZIP. On Windows, choose Extract All; on macOS, double-click the ZIP; on Linux, use your archive manager. Work in the extracted agent-arduino-main folder, not inside the ZIP.
  3. In the IDE, open Boards Manager, search for UNO Q, and install the Arduino UNO Q Zephyr core. These sketches were originally compiled with arduino:zephyr version 0.56.0. Start with the current core; Serial support requires version 0.55.0 or later. If the package is missing, add https://downloads.arduino.cc/packages/package_zephyr_index.json in Preferences under Additional Boards Manager URLs, then search again.
  4. Open Library Manager. Install Arduino_RouterBridge and ArduinoGraphics, including dependencies when prompted. The UNO Q core supplies Arduino_LED_Matrix, Wire, RTC, and Zephyr headers. Do not substitute an UNO R4 matrix library.
  5. Connect the UNO Q with the USB-C data cable. Select Arduino UNO Q in the board selector, then select its detected port under Tools → Port. Current IDE versions support the USB connection through the board's Linux side. A network connection may instead ask for the board's Linux password.
  6. Choose File → Open and open matrix-light-show/matrix-light-show.ino from your extracted folder. The folder and file must keep the same name.
  7. Click Verify (the checkmark). Wait for compilation to finish. A first build can take longer while tools prepare their caches. If it fails, follow the troubleshooting steps.
  8. Click Upload (the right arrow). Wait for the IDE to report that upload finished. You should see changing blue patterns on the built-in 13-column, 8-row matrix. You do not need to type any commands for this sketch.

First success: the matrix cycles through several effects. Next, open any other name/name.ino from the sketch instructions and repeat Verify → Upload. The games play themselves; they do not need a controller or an online AI service.

2B. Upload from the UNO Q's Linux terminal

The bundled flash helper runs on the UNO Q itself. It uses Python 3's standard library and the local Arduino tools. Do not run its upload path on your Windows, macOS, or ordinary Linux computer.

  1. Open Terminal on the board's desktop, or connect from your computer with SSH after first setup. In Windows PowerShell, macOS Terminal, or a Linux terminal, type the following with your actual board name:
ssh arduino@YOUR-BOARD-NAME.local

Replace YOUR-BOARD-NAME with the name you chose in App Lab. You can use the board's current IP address instead. Check that the SSH host is your board before accepting its first connection. Enter the board's Linux password; no characters appear while you type it. After login, the commands below run on the board. See Arduino's Linux terminal guide if you need help connecting.

  1. Download the repository in that board terminal. If Git or Python 3 is missing, install them with sudo apt update and sudo apt install git python3.
git clone https://github.com/mikersays/agent-arduino.git
cd agent-arduino

If you already cloned the repository, enter that folder instead. Save your edits before fetching an update with git pull --ff-only.

  1. Check the Arduino tools and install the libraries:
arduino-cli version
arduino-cli core list
arduino-cli lib install Arduino_RouterBridge ArduinoGraphics

If arduino-cli is missing, install it using Arduino's CLI installation instructions for the board's Linux ARM64 system, then reopen the terminal. If arduino:zephyr is absent from the core list, install it:

arduino-cli core update-index --additional-urls https://downloads.arduino.cc/packages/package_zephyr_index.json
arduino-cli core install arduino:zephyr --additional-urls https://downloads.arduino.cc/packages/package_zephyr_index.json

The helper expects the standard board installation under ~/.arduino15. If you customized the Arduino data directory, use the IDE path or restore a standard installation for this helper. Do not run flash with sudo; that changes the user and tool paths.

  1. Compile and upload your first light show:
python3 flash matrix-light-show

Read the replacement prompt, then type y and press Enter. The helper compiles first and uploads only after compilation succeeds. The changing blue patterns confirm the sketch is running. A compilation success alone does not mean an upload succeeded.

  1. Choose your next sketch with these commands:
python3 flash --list
python3 flash
python3 flash matrix-snake
python3 flash matrix-snake --compile-only

The interactive picker supports arrow keys, Enter, and filtering; if the terminal cannot display it, the helper falls back to a numbered list. The last command checks the code without replacing the running sketch. On a Git clone, ./flash is equivalent to python3 flash. The -y option skips the upload confirmation; beginners can leave it off.

Experienced users: compile and upload from another computer

Install Arduino CLI, the UNO Q core, and the two libraries on that computer as above. Run from the extracted repository folder. This network path requires the computer and board to be reachable on the same network:

arduino-cli board list
arduino-cli compile -b arduino:zephyr:unoq ./matrix-light-show
arduino-cli upload -b arduino:zephyr:unoq -p BOARD_IP ./matrix-light-show

Replace BOARD_IP with the current address from discovery or App Lab. On the board, ip -brief addr show wlan0 also shows the Wi-Fi address; omit its /24 or other network suffix. Type the Linux password when prompted. Keep this an interactive terminal session; do not put the password in a command or a script. The bundled helper's compiled files are in a separate cache, so run the compile command shown here before this upload command.

3. Control a sketch with text commands

A serial monitor displays messages from the sketch and sends your typed commands back. These examples call Serial.begin(115200). On the UNO Q, that connection travels through the Linux bridge.

Verification status: the repository records successful compilation of all 30 sketches on the original board. It does not yet record a successful end-to-end test of typed serial commands. The following commands match the code, but input through your IDE/core/bridge combination still needs a hardware check. Most animations work without input; the display server, stopwatch, and dice controls need that check for interactive use.
  1. Upload matrix-display-server. A dim pixel in the bottom-right corner is its expected idle display.
  2. Open Tools → Serial Monitor in Arduino IDE. Select 115200 baud and Newline (or Both NL & CR) for the line ending. Keep the UNO Q selected.
  3. Type HELP and send it. Then type BAR 75 and send it as a separate line. Do not include backticks or a shell prompt.
  4. Look for an OK reply and a progress bar on the matrix. This checks both command delivery and the visible response. Follow your chosen sketch's command examples next.

For the documented network monitor path, run this in an interactive terminal and replace BOARD_IP with your board's address:

arduino-cli monitor -p BOARD_IP -b arduino:zephyr:unoq -c baudrate=115200

Type one command per line and press Enter. Close the monitor with Ctrl+C before uploading again. If input does not reach the sketch, see serial troubleshooting. Some sketches print only at startup; missing an initial banner does not prove the sketch failed. The marquee processes commands between completed scrolls, so short messages respond sooner.

4. Make your first code change

Start with a change that has an obvious result:

  1. Open matrix-text-scroller/matrix-text-scroller.ino in the IDE.
  2. Find FIXED_MESSAGES and replace the text inside one pair of quotation marks with HELLO SAM. Keep the quotation marks, commas, and braces.
  3. Save the file, then click Verify and Upload. Wait through the message rotation to see your own words.
  4. Try changing SCROLL_SPEED_MS from 60 to 100. A larger interval makes scrolling slower.

In a board terminal, edit the same file with nano matrix-text-scroller/matrix-text-scroller.ino. Save with Ctrl+O, Enter; exit with Ctrl+X. Run python3 flash matrix-text-scroller to compile and upload your edit.

Change one value at a time and keep a copy of the original. To make a separate project, copy a sketch folder and rename both the folder and its .ino file to the same new name. The helper discovers matching folders automatically. Matrix drawing buffers have 104 pixels; grayscale values for matrix.draw() in these sketches range from 0 to 7. Text graphics use a different brightness API, so follow the existing text example.

5. Add a sensor when you are ready

All 30 sketches can start without external components. The scope and logger read floating-pin noise without sensors; the scanner can report an empty bus. The square-wave generator drives D13 immediately, so disconnect existing circuits before uploading it.

Power down and disconnect board power before changing wiring. For these beginner examples, keep analog input signals between 0 and 3.3 V, share GND with the signal source, and never connect a signal generator directly to another output. Follow the board's official pinout and electrical specifications for a particular peripheral.

For an optional analog test, connect a 10 kΩ potentiometer's outside terminals to 3.3V and GND, and its middle terminal to A0. After you check the wiring and restore power, turn it while running matrix-analog-scope or analog-csv-logger.

The supplied i2c-scanner uses Wire on the SDA/SCL header bus. The Qwiic connector uses Wire1 in the current Arduino documentation. A Qwiic device will not be scanned by this sketch as written; see its instructions.

Get unstuck

The board or port is missing
Wait for Linux to boot, try another data cable, and check the board in App Lab. Complete first setup. For network uploads, check the current IP and that both devices are on the same network. Follow the OS-specific discovery and Linux USB permissions instructions in the UNO Q manual.
The compiler cannot find a header
Install Arduino_RouterBridge and ArduinoGraphics in Library Manager. For Arduino_LED_Matrix.h, RTC.h, or zephyr/kernel.h, check that Arduino UNO Q is selected and its Zephyr core is installed. ArduinoGraphics must appear before Arduino_LED_Matrix in the text sketches; keep their include order.
The compiler reports an unsupported API or linking error
Record your core and library versions and the first error. The suite was originally compiled with core 0.56.0, and newer releases may differ. If a current core fails, you can select 0.56.0 in Boards Manager to compare. Close other builds and try Verify again; do not run concurrent builds in the same cache.
The upload asks for a password or says input is not supported
Use the board's Linux password in an interactive terminal, or SSH into the board and run python3 flash SKETCH_NAME there. Replace SKETCH_NAME with the folder name. The local helper avoids a second network password prompt.
The helper cannot find the core or remoteocd
Check arduino-cli core list as the normal board user. The helper searches ~/.arduino15/packages/arduino/; a different user or custom data directory will not match. Install the UNO Q core there, or use the IDE route.
The upload succeeds but the old app returns
Stop the running App Lab app and disable its startup setting before uploading again. Check that you selected the intended board. The MCU runs one sketch at a time.
The monitor is blank or commands do nothing
Confirm the selected sketch, board, 115200 baud, and newline setting. Try HELP, or STATUS for the stopwatch, timer, logger, and metronome. Wait for any text scroll to finish. Close other monitors. Try the documented network monitor path above. For output diagnostics on the board, arduino-app-cli monitor is another option; it is not a verified replacement for command input. Record whether output works separately from input. If replies still never arrive, use a self-running sketch while reporting the bridge issue; reflashing the same code repeatedly will not establish that input works.
The screen seems blank
The display server starts with one dim pixel. The stopwatch starts paused. The scanner uses serial output and the built-in LED, not the matrix. Compare with the expected behavior in the sketch's instructions; try matrix-light-show to check the display.

If you need help, open a GitHub issue with the sketch name, operating system, IDE/CLI version, core/library versions, upload method, first error, and expected versus actual behavior. Remove passwords and private network details. You can also ask the Arduino community.

For smaller programs or a Python/MCU app, follow the three extra teaching examples: Blink, Matrix Heart, and LED Toggle.
